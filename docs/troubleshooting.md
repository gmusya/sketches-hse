# Распространённые проблемы с окружением

## Не получается сдать задачу

## `ssh: connect to host gitlab.aysumg.ru port 2224: Connection refused`

Скорее всего, вы находитесь в необычной сети, например, в сети ВШЭ, в которой не разрешены соединения к некоторым портам. Попробуйте сменить сеть.

## `git@gitlab.aysumg.ru: Permission denied (publickey)` при попытке сдать задачу

Это означает, что публичный SSH-ключ либо не прописан на Gitlab, либо прописан с ошибкой. Посмотреть список зарегистрированных SSH ключей можно в настройках на gitlab.aysumg.ru (`Preferences` -> `SSH Keys` -> `Your SSH keys`). Там же можно добавить новый ключ.

Если вы работаете с репозиторием на виртуальной машине, то генерировать SSH-ключ нужно также на ней.

Если вы уверены, что добавили правильный ключ, но ошибка не уходит, то можно сравнить SHA256 хэши ключа на Gitlab (указан на странице ключа в настройках) с тем, что используется при аутентификации (можно найти в выводе `ssh -v -p 2224 git@gitlab.aysumg.ru` в строчке вида `Will attempt key...`).

**Обратите внимание, что используется порт 2224**.

## `fatal: No such remote 'student'` при попытке сдать задачу

Выполните `git remote -v`. Вывод должен выглядеть так:

```
origin  https://gitlab.com/sketches/public-2026-spring (fetch)
origin  https://gitlab.com/sketches/public-2026-spring (push)
student ssh://git@gitlab.aysumg.ru:2224/sketches/students-2026-spring/yourname.git (fetch)
student ssh://git@gitlab.aysumg.ru:2224/sketches/students-2026-spring/yourname.git (push)
```

Важно, что у `student` должен быть указан именно SSH URL (начинается с `git@gitlab.aysumg.ru`). Если у вас что-то не так, то пересоздайте remote:
```
git remote remove student
git remote add student ssh://git@gitlab.aysumg.ru:2224/sketches/students-2026-spring/yourname.git
```

## Проблемы в CLion IDE

Симптомы:
* не работает навигация по коду, появились странные ошибки
* неактивны кнопки `Build` / `Run`
* не получается выбрать таргет для сборки
* не работают подсказки в коде
* нет вкладки CMake на нижней панели

Что стоит сделать:

0. Если раньше все работало:
    * Перезагрузите CMake-проект (кнопка слева вверху на вкладке CMake внизу)
    * Если не помогло, перезагрузите CMake-проект со сбросом кэша (кнопка слева внизу на той же вкладке -> `Reset Cache and Reload Project`)
1. Проверьте, что CLion открыт в `sketches-hse`, а не в какой-то его поддиректории
2. Проверьте, что установлена свежая версия CLion
3. Если проблема остается, удалите директорию `.idea` в репозитории и перезагрузите IDE. Это сотрет настройки рабочей области, такие как сборочные конфигурации - их нужно будет пересоздать.
